# Resolved decisions

Resolutions of the open questions in `design.md` §10, plus environment facts.

## Environment
- Blender 5.2.2 LTS, bundled Python 3.14 (a distribution-packaged Blender may use the system `/usr/bin/python3.14`). Grease Pencil is the v3 API (`bpy.types.GreasePencil` with layers, drawings and attributes) — the 4.2-era GP API does not apply.
- Extension format: `blender_manifest.toml`, minimum Blender 5.2: the Grease Pencil v3 API, and the lock's wheels are built for its Python 3.14, so an older Blender would install the extension and then fail.

## Agent process
- **Python**: Blender's bundled Python. The extension creates a private venv from Blender's `sys.executable` and installs `agent_env/requirements.lock` with `--require-hashes --only-binary :all: --no-deps`, after user confirmation in preferences. Never auto-upgrades.
- **SDK**: `claude-agent-sdk==0.2.167`, exact pins + hashes in `agent_env/requirements.lock`. The wheel bundles the Claude Code CLI (`claude_agent_sdk/_bundled/claude`), so no separate CLI install is required.
- **Dev venv**: `.venv/` at the repo root, made from Blender 5.2's Python 3.14 with the lock installed the way the add-on installs it (README, Development). Use `.venv/bin/python` for agent-side code and tests. Do not install anything else.
- **Auth** (changed 2026-10-23): an Anthropic API key only: the preference, else `ANTHROPIC_API_KEY` in Blender's environment. No key, no agent; the sidebar asks for one. The agent's environment loses every other Claude or Anthropic credential variable and the bundled CLI runs with Whittle's own `CLAUDE_CONFIG_DIR`, so it can never sign in with the user's claude.ai login, nor read their Claude settings, hooks or MCP servers (architecture §2, Authentication). Why: Anthropic does not allow third-party products built on the Agent SDK to offer claude.ai login or use subscription plan limits; developers are to use API key authentication. The earlier default, the user's existing Claude login, is gone.
- **Telemetry** (changed 2026-10-23): the agent runs with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, so the bundled CLI sends no usage telemetry or error reports of its own. The preference **Send Claude Code usage data** (off) leaves the variable unset, and Blender's own environment, if it sets it, still wins. Why: Whittle's privacy promise is that only the turns go to Anthropic; telemetry is opt-in.
- **Model**: per chat, picked from the button beside Send (the newest of each family, older versions in a submenu, any id by hand); new chats start on the preference, default `claude-opus-5-5`. The list comes from the Models API through the key (older versions included), else the bundled CLI's initialize response, cached in the user folder over a bundled list (architecture §15). A change applies from the next turn via `set_model` in the same SDK session.
- **Effort** (2026-10-23): per chat, Low, Medium or High from the model menu; new chats run at High, with no preference. Opus 5.5 defaults to medium, and multi-step modelling turns gain from more thinking, so Whittle always sets it (`--effort`) rather than leaving it to the model. A change applies from the next turn in the same session via the CLI's `apply_flag_settings` control request, since the Python SDK has no effort method; restarting the session would also work but costs a reconnect.
- **Progress notes** (2026-10-23): Claude's short notes between tool calls are shown as its text. On Opus 5.5 they arrive as narration thinking blocks, which the bundled CLI requests (thinking display `updates`) as long as no explicit display is set, so Whittle sets none and turns narration blocks into text (architecture §5). Summarized thinking was the alternative; it is longer, reads as reasoning rather than as a message to the user, and would stop the updates.

## Behaviour
- **Branching**: fork the SDK session per branch. Each history node records the SDK session id at its completion; submitting from a non-leaf node resumes that session with `fork_session=True`.
- **Target lock**: removed (2026-10-23). It first warned the user and told the agent whenever the user touched the target during a turn, but it fired far too often (changing the viewport's shading counted) and the warning was noise. Now Whittle neither watches nor reports user edits during a turn: editing the target while Claude works is the user's call. Never block or revert the user.
- **Self-check renders**: Workbench at 512 px; `gpu.types.GPUOffScreen` viewport-draw path as the fallback if renders are too slow.
- **Self-check cap**: 3 rounds by default, configurable.
- **Distribution** (changed 2026-10-23): open source under GPL-3.0-or-later (the license Blender add-ons that import `bpy` take). Built from the repo with `build.sh`; not on extensions.blender.org yet. Branding follows Anthropic's Agent SDK guidelines: Whittle is its own product, "Powered by Claude" at most, never named or styled as Claude Code, and not affiliated with Anthropic.

## Shortcut
- **Key**: Shift+Alt+C (`whittle.type_prompt`, an add-on item in the Window keymap, so it works over any editor and in every mode, and is rebindable in Preferences → Keymap). C for Claude or chat, and one hand reaches all three keys. It is unused in Blender 5.2's default keymap outside modal maps, which only apply while their own operator has the keyboard (C toggles clamping while moving or bevelling); `tests/blender/test_shortcut.py` checks this against the default keymap's source. Background Blender has no key configurations (`wm.keyconfigs.default` is empty), so the keymap was dumped from `presets/keyconfig/keymap_data/blender_default.py`, the source Blender builds it from. Rejected: Alt+Space, which desktops often take (launchers, the window menu); Shift+Space (the tool menu); Ctrl+Shift+Alt combinations, hard to hit with one hand; F-keys, far from the home row.
- **Popup, not the sidebar's box**: Python cannot start editing a sidebar field. So the shortcut opens the sidebar on the Whittle tab (`Region.active_panel_category` is writable in 5.2.2, but only once the region has drawn and listed its tabs, so a hidden sidebar is retried on a timer) and `wm.call_panel(keep_open=False)` of a panel under the pointer whose field has `UILayout.activate_init`, as Blender's own F2 rename does.
- **One line**: the multi-line `textbox` ignores `activate_init` (checked in a GUI Blender: nothing typed reached it), so the popup holds a one-line `prop` of the same string. Shift+Enter cannot add a line there; long prompts belong in the sidebar.
- **Panel popup, not a props dialog**: in `invoke_props_dialog` the first Enter only ends text editing and a second presses the dialog's button. In a panel popup Enter confirms the field and closes the popup on the press, so the release reaches `whittle.enter_send` and one Enter sends, exactly like the sidebar's box. Checked in a GUI Blender with `--enable-event-simulate`: Shift+Alt+C, typing and Enter sends a prompt, an amendment and an answer with the fake agent, in Object Mode, Edit Mode and sketching; Esc sends nothing and keeps a draft.

## Chats
- **Model**: a file holds many chats; each has its own conversation, history tree and SDK sessions (its folder is the agent's cwd). Switching chats leaves the scene as it is and only changes the conversation and the agent's context; the next turn starts from the scene as it is, with a context note. New Chat and switching wait for a running turn.
- **Storage**: everything is stored inside the `.blend`, so the file alone carries every chat. Each chat is one zip (`.png`/`.blend` stored, JSON deflated; turn checkpoints and comparisons left out) in a `bytes` ID property on a hidden `.whittle` Text, written in `save_pre` and removed in `save_post`; `load_post` unpacks into the file's cache and removes it. Why: `bytes` ID properties are exact, fast (5 MB in 2 ms) and leave the file when deleted (5.54 → 0.54 MB on the next save). Kept in Blender's data between saves they would make every undo step slower (6 vs 1 ms per push at 50 MB), hold the payload twice in memory, and let Ctrl+Z roll chat data back with the scene; written only around a save they cost undo nothing. Rejected: Text datablocks with base64 (a 6.8 MB line hung Blender; 3× the size in lines), packed files (only images, sounds, fonts and volumes), snapshots as real datablocks (in every undo step, the outliner and the user's file data).
- **Cache** (changed 2026-10-23): nothing is written beside a `.blend`. The working copy is a hidden cache, `<user dir>/cache/<file id>/`, named by a random id stored in the `.blend` (a string ID property on the same Text, kept in the data), so it survives renames and moves; an unsaved file gets its id with its first chat and keeps the cache when saved, so nothing moves on a save. A copy opened while the original's cache is claimed by a live Blender, or whose cache records a different file that still exists, gets a fresh id (copy-on-conflict), so two files never share one cache; until the copy is saved with that id, each open finds the same cache again by its recorded path, so a crash before the first save loses nothing and no stray caches pile up. The `.blend` stays the truth: opening it fills the cache from it and a differing cache copy is deleted, except for crash recovery: when the cache's recorded `base` (a stamp of the index and zips the `.blend` last stored or opened with) equals the opened file's, the cache's newer work stays, since Blender's autosave and crash files carry no chats. Caches not used for 30 days are deleted whenever a file is opened (and when the add-on is enabled with one open), never the open one. Why: folders beside a `.blend` are clutter; the earlier `<name>.whittle/` sidecar (and `.replaced-<time>/` folders on conflicts) cluttered every folder with a saved `.blend`. Repacking only chats whose folder changed (a stat fingerprint) keeps saves fast.
- **SDK transcripts**: carried with the chat through the SDK's `SessionStore` (a folder store in the chat's `sdk/`), so a chat resumes on another machine or after the file moved. They count towards the chat's size (about 0.1–0.3 MB per turn with render images).
- **Deletion**: a chat is deleted from its trash icon or in bulk (all others, or older than a week, a month, three months), always after a confirmation; it leaves the cache and the CLI's project folder for its cwd at once and the `.blend` at the next save. The menu shows each chat's stored size so growth is visible. Deleting the current chat switches to the most recent remaining one, or a new empty chat.
- **No migration** (changed 2026-10-23): the code that moved earlier layouts into the cache (a single-session folder, the `<name>.whittle/` folder beside a file and its `.replaced-<time>/` copies, the user folder's `caches/<sha1>/` and `dev-sessions/`) is gone. Why: those layouts come from development builds before 0.1.0, which no released file uses, and the code had to be carried and tested through every change to the cache.
- **Same file in two Blenders**: the second still gets a cache of its own (copy-on-conflict), so neither overwrites the other's chats; while the other's claim is live, the sidebar has one quiet line: "This file is open in another Blender; chats here won't merge with it." Why: merging two caches of one file is not worth its complexity, but silently diverging chats surprised.
- **Chats from another machine**: each chat records the install that made it (`origin`, a random id in Whittle's user folder, `install.json`, naming no person or machine). A chat whose origin is another install opens read-only with a box, "Continue this chat?" [Continue]; Send is disabled with a tooltip until then, and New Chat stays available. Continue records this install in the chat's `adopted` list, stored with the chat, so it never asks again here, and the file saved from here carries that. Chats from before the marker count as this install's: no prompt for existing files. A user's own chats ask once on each of their other computers too; that is intended. Why: continuing a chat replays its conversation to Claude as if it were Claude's own, so text planted in someone else's file could steer it (README, Security); one click is cheap, and the default is the safe one.
